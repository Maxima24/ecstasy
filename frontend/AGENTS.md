# Frontend stack rules

The block above is generated by `next dev`. Everything below is ours; keep it.
Repository-wide rules are in the root `AGENTS.md` and `RULES.md` — this file
does not replace them.

## The one rule that is easy to break

Server code here is a **backend-for-frontend proxy, never an implementation**
([ADR-0001](../docs/decisions/0001-frontend-stack-nextjs.md)).

Route Handlers and Server Actions **may** proxy and aggregate backend calls,
hold httpOnly session cookies and refresh tokens, attach credentials to backend
calls, and reshape payloads for presentation.

They **may not** implement domain rules, decide authorization, or open a
database, cache, queue, or object-store connection. Forward credentials; never
decide access. The backend is the authorization boundary.

## Also not optional

- All work stays under `frontend/`, on the `frontend` branch or a
  `feat/frontend/<issue>-<slug>` branch off it.
- No data-store driver in `package.json`.
- No secret reachable from a `NEXT_PUBLIC_*` variable — those are public by
  definition.
- Until a contract exists under `contracts/`, build against fixtures. Do not
  read the backend source tree and do not infer an interface from it.
- Never commit a secret value. Environment variable **names** only.
